# 予約受付台帳 — STEP 8

HTML / CSS / JavaScriptだけで動作する学習用のローカル予約システムです。外部ライブラリ、Node.js、ビルド、バックエンド、DBはアプリ本体に使用しません。

## 起動と予約登録

1. `index.html`をEdgeまたはChromeで直接開きます。通常のスクリプトを順番に読み込み、ES Modules・fetchは使用しません。
2. ICSは任意です。外部予定も確認する場合は「ファイルを選択」またはドラッグ＆ドロップでICSを読み込みます。複数ファイルに対応します。講座のサンプルは`samples`のICSです。名前（結合文字を含む）と内容は変更していません。
3. 前週・次週・今週で希望日へ移動し、緑の枠を選択します。過去の週にも移動できます。
4. 氏名・メールアドレスを入力します。ICS未読み込みの場合は外部予定未確認の説明を読み、確認チェックを入れてから「予約を確定する」を押します。読み込み済みの場合はチェック不要です。氏名は前後空白を除いて1〜100文字（Unicodeコードポイント）、メールは前後空白を除いて254文字以内でブラウザのemail形式検証を使用します。
5. 保存成功後にメッセージを表示し、枠は淡い赤になり、予約一覧と管理者一覧へ反映されます。

受付は日本時間の月〜金9:00〜18:00、30分単位（最終枠17:30〜18:00）。過去・開始済みの枠、ICS予定あり、確定予約ありの枠は予約できません。ダイアログを開いた後でも、確定直前に現在時刻・ICS・保存済み予約を再確認します。ICS読み込み中・エラー中は確定できません。未読み込み時は外部予定未確認の確認チェック後に確定できます。未読み込み時の緑枠は外部予定まで確認済みという意味ではありません。

通常の予約モードではグレーはICS予定、淡い赤は確定予約で、ともに選択できません。予約とICSが重なった場合は赤を優先し、日時付き競合警告を表示します。既存予約は自動削除しません。STEP 1のデモ予約2件は削除しています。

新規予約ダイアログは「入力をやめる」で保存せず終了します。「予約を確定する」、キャンセル確認の「戻る」「キャンセルを確定する」は従来どおりです。右上の×とEscでも入力を中止できます。

## ICSの任意化と確定前の確認（STEP 6）

ICSファイルを毎回読み込まなくても、新規予約・予約日時変更ができます。未読み込み時は保存済みの確定予約だけで判定します。**外部カレンダーとは重複する可能性があり、実際の顧客向けサービスとしての安全性を保証するものではありません。** 画面上部と各確認ダイアログに案内を表示します。緑は保存済み予約のない枠を意味し、外部予定まで確認済みという意味ではありません。保存済み予約は未読み込みでも赤で表示します。

| 状態 | 確認対象・確定条件 |
| --- | --- |
| 未読み込み | 保存済み確定予約のみ。ダイアログの「外部カレンダーの予定は未確認です…」確認チェック後に確定可能。 |
| 読み込み中 | 完了まで新規予約・日時変更の確定を禁止。以前の同意は解除。 |
| 読み込み成功 | 保存済み確定予約と読み込んだICS予定の両方を確認。未確認チェックは不要。 |
| エラー | 未読み込みへ自動移行せず、エラー内容を表示して確定を禁止。以前の正常データ・予約は保護。 |

未読み込み時は、氏名・メール・日時を確認してからチェックを入れます。チェックを外すと再び確定できません。通常予約と日時変更の同意は共有しません。ダイアログを開き直した場合、読み込み開始・完了・エラー、クリアなどICS状態が変わった場合は同意を解除します。同意はメモリ上だけの一時的な確認で、localStorageには保存しません。保存直前にも現在のICS状態とその操作の同意を検証します。

Medium指摘への対応として、`bookingContext()` は状態・予定・同意booleanのコピーではなく、確認操作に対応する一時トークンを返します。トークンの記録は非公開のWeakMapに保持し、新規予約／日時変更の種別、ダイアログを開くたびの操作世代、選択枠、同意の更新回数、ICS読み込み世代・更新番号を結び付けます。解除後に再チェックした場合、閉じて再表示した場合、ICSの開始・完了・クリア・エラー後も以前のトークンは再利用できません。保存成功後はトークンを消費します。

保存処理の最新状態取得元は、画面起動時に一度だけ接続する検証関数です。現在のICS管理状態・予定Map、現在開いているダイアログとチェック欄を取得して照合します。呼び出し側の`icsStatus`・`events`・`externalAcknowledged`は保存判断に使用しません。保存直前に最新の予約データも再取得し、処理中に変わっていれば上書きせず再確認を求めます。未初期化・未発行・別操作・別枠・古いトークンでは保存しません。これらはローカル画面内の整合性保護で、本人認証やサーバー側のアクセス制御を提供するものではありません。

複数ファイルの一部や追加ファイルが失敗した場合も確定を禁止します。同じ読み込みキュー内の後続成功で先のエラーを消しません。処理完了後、正常なICSを再選択すると読み込み済みへ復帰できます。全て取り込み直す場合はクリアして必要なファイルを再選択してください。明示的なクリアでも未読み込みへ復帰できますが、外部未確認への新たな確認チェックが必要です。クリアは予約を削除しません。

クリア時は処理中のFileReaderを中止し、新しい世代のキューを独立させるため、古い処理の完了を待たず再取り込みできます。旧世代の遅延した完了・失敗通知は反映しません。読み込み中に以前の同意で確定することはできません。

**読み込み成功は予定の最新性を保証しません。** 選択したICSの内容だけで判定し、Google Calendar等とは同期しません。最新のICSを書き出して読み込んでください。ICSは保存しないため、再読み込み後は未読み込みに戻ります。保存済み予約は復元し、ICS再選択または未確認チェックによって予約操作を続けられます。

STEP 5は利用者のWindows Edge実機で17〜21件目の登録、確定予約とキャンセル履歴の2ページ目、日時変更と新旧枠の表示を確認済みです。STEP 6も利用者のWindows Edge実機でICSなしの登録・同意制御・日時変更・重複防止・保存・ページ切り替えを確認済みです。STEP 7のWindows Edge実機確認は未実施です。予約件数による上限は設けていません。

## 予約日時変更（STEP 5）

1. 確定予約カードの「日時変更」を押します。現在の日時・氏名・メールが表示され、週間カレンダーが日時変更モードになります。
2. 前週・次週で移動し、変更先の空き枠を選びます。月〜金9:00〜18:00の30分枠で、終了は開始の30分後です。過去・開始済み、ICS予定あり、他の確定予約がある枠へは変更できません。
3. 変更前・変更後を確認します。ICS未読み込みの場合は変更専用の外部予定未確認チェックを入れ、「変更を確定する」を押します。ICS読み込み済みの場合はチェック不要です。自身の予約は重複判定から除外しますが、同じ日時への変更は不要として案内します。
4. 保存成功後のみ完了を表示し、元の枠を解放して変更先を予約済みにします。元の枠にICS予定がある場合は予定あり表示です。検索・表示順・ページ、管理者一覧も更新します。

「変更をやめる」やEscでは保存せず、通常の新規予約モードへ戻ります。別枠を選び直す場合は、一覧から再度「日時変更」を押してください。中止・成功後は対象カードの「日時変更」へフォーカスを戻し、日付検索や並べ替えで現在のページから消えた場合は予約一覧見出しへ移動します。キャンセル履歴には日時変更操作はありません。

ID・氏名・メール・createdAt・status・cancelledAtを維持し、start/endだけを書き換えます。STEP 3・STEP 4と同じ保存キー・version 1の形式を使い、監査履歴や追加フィールド、移行処理はありません。キャンセル履歴もそのまま保持します。保存失敗時は成功と表示せず、元データを保持します。

変更開始時の予約内容を保持し、保存直前に最新のlocalStorageを読み直して照合します。別タブの変更・キャンセルを検出した場合は上書きを拒否するので、中止して一覧からやり直してください。変更先の現在時刻・ICS・最新の他予約も保存直前に再確認します。ただしlocalStorageはトランザクションではなく、同時の読み取り・書き込みや変更後に元へ戻した操作の完全な検知は保証できません。複数PC共有・本人認証・管理者認証はありません。

## 予約一覧・キャンセル・管理者表示

「確定予約」はconfirmedのみを予約日時の昇順で表示し、既存のキャンセル操作・ICS競合警告を利用できます。「キャンセル履歴」はcancelledのみを表示する参照専用タブで、氏名・メール・元の予約日時・キャンセル日時（日本時間）を確認できます。キャンセル・日時変更ボタンや復元・削除機能はありません。各タブの件数は検索前の状態別総数です。過去の予約も残ります。それぞれ0件のメッセージを表示します。

氏名・メールアドレス検索欄に一部を入力すると即時更新します。前後空白を除去し、英字の大文字・小文字を区別しません。空欄または空白のみで全件に戻ります。「予約日」は日本時間の予約開始日で絞り込み、履歴では元の予約日を使います。未指定で全期間、「日付をクリア」で解除できます。文字検索との組み合わせも可能です。該当なしは専用メッセージを表示します。

結果は1ページ20件です。「前のページ」「次のページ」、現在／総ページ数、該当件数・表示範囲を確認できます。タブ・検索条件の変更は1ページ目に戻り、キャンセルや別タブの更新でページ数が減った場合は有効な最終ページへ補正します。0件は0〜0件・1 / 1ページとなり、端の移動ボタンは無効になります。タブはTabで移動し、左右矢印・Home・Endでも選択できます。

一覧の「キャンセル」から内容確認ダイアログを開き、「キャンセルを確定する」で保存します。「戻る」やEscでは変更しません。保存成功後はキャンセル状態となり、同じ枠にICS予定がなければ空きに戻ります。キャンセル済み予約は履歴タブへ移動し、再キャンセルできません。

本人確認はありません。**このブラウザに保存された予約を操作できる**仕様であり、メールアドレスによる本人認証は行いません。

`#admin`は「ローカルデモ・認証なし」の全予約一覧です。認証付きの管理者専用画面ではなく、このブラウザの保存データだけを表示します。他のPCや利用者の予約を取得する仕組みはありません。状態（すべて／確定／キャンセル済み）・氏名／メール検索・予約日を組み合わせ、20件単位で閲覧できます。全件数・確定件数・キャンセル件数は検索前の総数、ページ下部は検索後の該当件数です。受付画面と管理者画面の検索条件は独立しています。

## 保存と個人情報の注意

- STEP 6でもSTEP 3〜STEP 5の保存形式を変更していません。検索・フィルター・ページ切り替えは画面内だけで処理し、保存データを書き換え・削除・初期化・移行しません。
- localStorageキーは`reservation-ledger.bookings.v1`、形式は`{ version: 1, reservations: [...] }`です。
- 各予約は`id, name, email, start, end, status, createdAt, cancelledAt`を持ち、時刻はUnixミリ秒です。statusは`confirmed` / `cancelled`、未キャンセルのcancelledAtはnullです。
- IDはcrypto.randomUUID、未対応ならcrypto.getRandomValuesによる128ビット乱数を使用し、既存IDとの一致も検査します。安全な乱数が使えない環境では登録をエラーにします。
- 登録・キャンセル・日時変更時に保存し、再読み込み・ブラウザ再起動後に復元します。キャンセルも履歴として残ります。保存完了前には成功と表示しません。
- 氏名・メールアドレスはこのブラウザに残ります。共有PCや共用プロフィールでは他の利用者にも閲覧・操作され得ます。ブラウザのデータ削除で予約も失われます。本人認証、暗号化保管、メール送信はありません。
- 保存データのバージョン・型・入力値・日時・状態・ID重複・有効予約の重複を検証します。不正データは自動削除・上書きせず、登録・キャンセル・日時変更を停止して日本語エラーを表示します。表示済みの正常データがある場合は保持します。必要なら開発者ツールで保存データを確認し、バックアップしてから対象キーを修復・削除してください。
- 容量不足や保存アクセス拒否でもエラーを表示し、成功扱いしません。保存設定を修正して再試行してください。
- **ICS内容は保存しません。** リロードやブラウザ再起動後には最新の予定確認のため再度ICSを読み込んでください。ICSを再選択しない場合も、外部未確認へのチェック後に操作できます。保存済み予約は表示し、同じ枠への重複を防ぎます。
- 保存領域はブラウザ・プロフィール・オリジンに依存します。複数PC・複数利用者間では予約を共有しません。別ブラウザや別URLでは同じ予約を見られません。プライベートモード等では終了時に消えることがあります。
- file://のlocalStorageの扱いはブラウザに依存します。ファイル移動・名称変更・ブラウザ設定変更で保存領域が変わったり利用できなかったりすることがあります。アクセスできない場合は保存をエラーにします。

## 複数タブと競合

同一オリジンの別タブで予約・キャンセル・保存データの削除が行われると、storageイベントで一覧とカレンダーを更新します。確定時とキャンセル時には保存データを再取得します。

ただしlocalStorageの読み取り・書き込みは一連のトランザクションではありません。**完全に同時の複数タブ操作では、二重予約の判定漏れや更新の上書きを防げません。** file://でのタブ間イベント・領域共有もブラウザ依存です。本番用の排他制御ではなく、学習用の制限です。共有PCで複数利用者の本人性を区別することもできません。

ICSを後から更新して既存予約と競合しても、予約は保持し警告します。ICSの同じUIDは後から正常に読み込んだ内容で更新します。SEQUENCE等の新旧判定や削除同期はありません。取り込みを全て入れ直す場合は「読み込んだ予定をクリア」から再選択してください。ICSのクリアは予約を削除しません。

## CSV・ICSエクスポート（STEP 7）

予約一覧の「予約データの出力」から操作します。エクスポートは読み取り専用で、保存キー・version・予約データ・キャンセル履歴を変更しません。検索条件・タブ・表示ページには関係なく、選択した対象を全件出力します。出力前に対象件数と個人情報の注意を表示し、「ダウンロードする」で開始します。「出力をやめる」またはEscで中止できます。対象0件では案内を表示し、ファイルは作成しません。

### CSV出力

1. 「CSVの出力対象」で確定予約のみ／キャンセル履歴のみ／すべての予約を選びます。
2. 「CSV出力」を押し、件数と個人情報の注意を確認してダウンロードします。
3. 出力日の日本時間を含む `reservations-all-2026-06-29.csv` などのファイルをExcel等で開きます。

列は予約ID、氏名、メールアドレス、予約日、開始時刻、終了時刻、状態、登録日時、キャンセル日時です。日時は日本時間、状態は「確定」「キャンセル済み」です。キャンセル履歴は元の予約日を使用し、キャンセル日時がない場合は空欄です。

UTF-8 BOM付きで、全セルをダブルクォーテーションで囲み、カンマ・引用符・改行をエスケープします。数式として解釈される可能性のある先頭記号（`= + - @`、空白・制御文字に続く場合を含む）や先頭タブ・改行にはアポストロフィを付けて中和します。そのため元の値と表示が異なる場合があります。Excelで文字化けする場合はテキスト／CSV取り込みでUTF-8を指定してください。Excelによる日付やIDの自動変換を避けたい列は文字列として取り込んでください。

**CSVには氏名・メールアドレスが含まれます。** ダウンロード先・共有先に注意してください。CSVは確認・集計用で、完全なバックアップ復元用ではありません。数式対策による値の加工、日時の表示形式への変換を行い、CSVインポート／復元機能はありません。

### ICS一括・個別出力

「ICS一括出力」は確定予約だけを全件出力します。確定予約カードの「ICS出力」はその1件だけを出力します。キャンセル履歴にはICS出力ボタンがなく、一括出力にも含めません。

初期設定の予定名は「予約あり」で、氏名を含めません。氏名を出す場合だけ「ICSの予定名に氏名を含める」にチェックしてください。この設定は一括・個別に共通で、出力確認画面にも表示します。メールアドレスは常にICSへ出力しません。匿名の予定でも日時という情報は含まれるため、ファイルの取り扱いに注意してください。

日本時間の予約枠をUTC（末尾Z）のDTSTART／DTENDへ変換します。DTSTAMPとSUMMARYを含み、CRLF改行、UTF-8で75オクテット以内の行折り返し、テキストのエスケープを行います。UIDは予約IDからSHA-256で生成する安定した値です。IDをそのまま出さず、予約IDに個人情報が含まれていてもICSへ直接露出させません。Web Crypto（crypto.subtle）を利用できない環境では、ICS出力をエラーにします。対応ブラウザで開くか、開発用localhost配信を利用してください。

Googleカレンダーでは設定のインポート、Outlookではカレンダーのファイル取り込み、Appleカレンダーではファイルの読み込みからICSを選びます。メニュー名・手順は製品やバージョンによって異なります。自動テストでは実ファイルを独立したiCalendarパーサーで解析していますが、利用者のGoogleカレンダーでSTEP 7のICS取り込みは成功済みです。Excel・Outlook・Appleカレンダーでの実取り込みは未検証です。

**ICSは自動同期ではありません。** 同じ予約は同じUIDで出力し、日時変更後は新しい日時を反映しますが、再取り込み時の既存予定の更新・重複排除はカレンダーアプリによって異なり、保証しません。不要な重複がないか取り込み先で確認してください。**予約をキャンセルしても、過去に外部カレンダーへ取り込んだ予定は自動削除されません。** 外部側で手動削除してください。外部の予定を更新・削除する機能はありません。

### 最新データと失敗時の扱い

確認画面を開く時とダウンロード実行直前にlocalStorageを読み直します。確認後やICS生成中に対象が変わった場合はファイルを作らず、更新した件数を表示して再確認を求めます。読み取り拒否・破損データ・未知のversionなどの異常時は、古い画面情報へ代替せず出力を停止します。元の保存データは変更しません。

ファイルはブラウザ内のBlobで生成し、外部サービスへデータを送信しません。オブジェクトURLはブラウザが取得できる猶予を置いて60秒後、またはページ離脱時に解放します。「ダウンロードを開始しました」はブラウザへの開始指示を意味します。端末への保存完了はダウンロード一覧で確認してください。

## JSONバックアップ・復元（STEP 8）

CSVはExcel等での閲覧・集計、ICSは外部カレンダーへの取り込み、JSONはこのシステムの予約データのバックアップ・復元用です。管理者画面（`#admin`）の「JSONバックアップ・復元」欄から操作します。管理者画面に認証はなく、ローカルの学習用アプリです。

### バックアップを保存

「バックアップを保存」を押し、個人情報の注意と全件数を確認して「JSONをダウンロードする」を押します。`reservation-backup-2026-06-29.json`など、日本時間の出力日を含むUTF-8 JSONを保存します。検索・タブ・ページの条件によらず全予約を含め、0件もバックアップできます。出力自体はlocalStorageを変更しません。確認後に保存データが変わった場合は再確認を求めます。

バックアップは次のように、内部の保存形式を専用の外側の情報で包みます。

```json
{
  "format": "reservation-ledger.backup",
  "backupVersion": 1,
  "exportedAt": "2026-06-29T00:00:00.000Z",
  "reservationCount": 0,
  "data": { "version": 1, "reservations": [] }
}
```

`exportedAt`はUTCの作成日時、`reservationCount`は全件数、`data`は予約ID・氏名・メール・開始／終了・createdAt・cancelledAt・statusを持つ従来の保存形式です。キャンセル履歴と過去予約も含めます。バックアップ形式のバージョンとlocalStorageのバージョンは別に検証します。

**JSONには氏名・メールアドレスなどの個人情報が含まれます。暗号化は行いません。** 信頼できる端末の安全な場所に保存し、第三者に共有しないでください。ファイルはブラウザ内で生成し、外部サービスへ送信しません。自動バックアップは未実装なので、必要な時に手動保存してください。端末やブラウザの保存領域を削除する前に、ダウンロードしたファイルが存在することを確認してください。

### JSONファイルのサイズ上限

出力・復元ともに**UTF-8で5MiB（5,242,880バイト）以下**を扱います。境界ちょうどは許可し、1バイトでも超えた場合は停止します。`ReservationBackup`の共通定義で、出力のUTF-8サイズ・入力の`file.size`・読み込み結果・直接のJSON解析を確認します。上限はブラウザの保存容量とは別のアプリ仕様です。

通常の数十件の学習用予約より十分大きい範囲を確保しつつ、無制限の読み込み・解析による画面停止とメモリ負荷を抑えるための上限です。レビューで確認した約64MiBの不正な氏名を含むファイルは、内容を読み込む前に拒否します。サイズが不正または取得できない場合も安全に停止します。日本語で理由を表示し、別の正常なファイルを選択して続けられます。保存データは変更しません。

バックアップ出力が上限を超える場合もダウンロード前にエラーにします。予約を切り捨てたり、一部だけ出力したりはしません。出力できたバックアップは同じ上限の復元処理で読み込めます。ただし復元先の保存容量が足りなければ、既存の保存エラー処理で停止します。

氏名は前後空白を除いて1〜100 Unicodeコードポイント、メールは254 UTF-16コード単位以内という既存の制限を維持します。氏名は200 UTF-16コード単位を超えれば配列化する前に拒否し、その範囲内でコードポイント数を確認します。絵文字100文字（200コード単位）も正常に扱います。メールは長さを確認してからDOMのemail形式検証へ渡します。

Web Workerは採用していません。対象を通常の数十件のローカル利用に限定し、5MiBで負荷を制限して既存のDOMによるメール検証を再利用する構成を維持します。最大サイズでは同期処理中に短い応答遅延が残り、端末性能によって長くなる場合があります。大容量を常用する設計や、常に即時中止できる非同期解析は今回の対象外です。

### バックアップから復元

1. 管理者画面で「バックアップから復元」を押し、JSONファイルを選択します。
2. 形式・バージョン・作成日時・件数・全予約の検証完了を待ち、現在の件数とバックアップの件数を確認します。選択だけでは書き込みません。
3. 保存領域が空なら「復元を確定する」で復元します。
4. 既存データがある場合は**現在の予約をすべて置き換えます**。まず「復元をやめる」で戻って現在のバックアップを取得してください。改めてファイルを選び、専用の置き換え確認チェックを入れて確定します。追加・統合はしません。0件のバックアップで置き換える場合は、現在の全予約が空になります。
5. 成功後は確定予約・キャンセル履歴・日時・一覧の件数・カレンダーを確認し、必要に応じて再読み込みして確認してください。

中止ボタン・Escでは書き込みません。中止／完了後は元の操作ボタンにフォーカスを戻します。確認を閉じた後は以前のチェックを再利用できません。復元で古い予約操作の同意・日時変更モードは終了し、再度の予約操作では従来どおり操作ごとの確認を行います。

予約検証は`Reservations.validateData()`を再利用します。重複ID、不正な氏名・メール・日時・30分枠、状態とキャンセル日時の矛盾、確定枠の重複などが1件でもある場合は全件を拒否します。バックアップ形式にない項目も拒否し、一部だけを無断で除外しません。過去日時は通常の新規登録とは異なり、履歴として復元します。不正なUTF-8を文字置換して受け入れず、不正なJSONや未知の形式・バージョンでは書き込みません。

実行直前に現在の保存文字列を読み直し、確認時と変わっていれば停止してファイルの再選択を求めます。別タブの登録・変更・キャンセル・削除によっても確認を無効にします。書き込みは検証済みデータを1回の`setItem`で置き換え、保存失敗時は既存データを保持します。読み取り不能・保存データ不正の場合も、画面に残る古い内容で復元せず停止します。破損した保存領域の強制上書き機能はありません。

保存キーは`reservation-ledger.bookings.v1`、内部形式は`{ version: 1, reservations: [...] }`のままです。外側のバックアップ情報はlocalStorageに保存しません。STEP 3〜7のデータを引き続き利用できます。

JSONにはICSの内容・読み込み状態・同意チェックは含めません。新しいブラウザではICS未読み込みのままです。復元時に現在読み込み済みのICSがある場合、その状態と予定は保持し、復元予約との競合は既存の警告に表示します。外部予定を確認したい場合は最新のICSを別途読み込んでください。

localStorageの読み取りと書き込みをまとめた完全なトランザクションはありません。完全に同時の別タブ操作では更新競合を防げない場合があります。複数PC間の自動共有、クラウド保存、本人認証・管理者認証はありません。手動ファイル移動で復元する場合も、取り扱いと置き換え対象を利用者が確認してください。

## ICS対応範囲と制限

VERSION 2.0のVCALENDAR / VEVENT、UID、DTSTART、DTEND、SUMMARY、STATUSを解析します。日時はAsia/Tokyo、UTC（Z）、タイムゾーンなし（Asia/Tokyo扱い）。終日はVALUE=DATEで終了日を含めず、DTENDなしなら1日とします。時刻付き予定はDTEND必須です。折り返し、改行・カンマ・セミコロン・バックスラッシュのエスケープ、正常な引用パラメーターに対応します。不正エスケープ、片側引用符、空TZID/VALUEはエラーです。CALSCALEは未指定かGREGORIANのみ。STATUS未指定はCONFIRMED、CANCELLEDはブロックしません。

以下はファイル単位でエラーにし、既存の正常な取り込みデータを保持します。

- 繰り返し（RRULE、RDATE、EXDATE、EXRULE、RECURRENCE-ID）。
- Asia/Tokyo以外のTZID、VTIMEZONE、VALARM等の追加コンポーネント。
- DURATION、TRANSP、未知の標準プロパティ・日時パラメーター。
- PUBLISH以外のMETHOD、VERSION 2.0以外、不正な日付・逆転した終了時刻。

DESCRIPTION、LOCATION、DTSTAMP等の補助情報とX-拡張は判定に使いません。X-WR-TIMEZONEはAsia/Tokyoのみ許可します。一般的なカレンダーの書き出しも、VTIMEZONE等を含む場合は取り込めません。
