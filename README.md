# 予約受付台帳 — STEP 2

HTML / CSS / JavaScriptだけで動作する学習用デモです。外部ライブラリ、Node.js、ビルド、バックエンド、DBは使用しません。

## 起動と操作

`index.html`をEdgeまたはChromeで直接開きます。通常のスクリプトを順番に読み込む構成で、モジュールやfetchは使いません。インターネット接続は不要です。

「ファイルを選択」またはドラッグ＆ドロップで、`samples`のICSを選択してください。実際のファイル名は結合文字を含みます。名前・内容とも変更していません。複数ファイルを追加できます。前週・次週で2026年7月〜10月へ移動して確認できます。

- ファイル名・ファイル内件数・UID重複除去後の合計件数・キャンセル件数を表示します。
- 同じUIDは後から正常に読み込んだ内容で更新します。ファイル間のUIDも共通に扱います。リビジョンやSEQUENCEによる新旧判定はしません。
- 不正ファイルはファイル全体を取り込まず、日本語エラーを表示します。他の正常ファイルや既存データは保持します。
- クリアは取り込みデータ・ファイル一覧を消去します。読み込み中のクリアでも古い結果は反映されません。
- 未読み込み時の緑枠はICS予定未確認です。読み込み後はICSと重ならない枠が緑、予定ありがグレー、学習用予約2件が淡い赤です。デモ予約とICSが重なる場合はデモ予約の赤を優先します。
- グレーと赤の枠は選択不可、緑から既存の入力ダイアログを開けます。予約は確定されません。
- データはメモリのみで保持し、ページを再読み込みすると消えます。

## 構成

- `js/app.js`：画面操作、ファイル読み込み、UID統合、描画。
- `js/ics-parser.js`：ICS解析と検証。
- `js/calendar.js`：東京の暦日、枠の日時、重複判定。描画から独立しています。
- `tests/test_browser.py`：検証環境用のPython Playwrightテスト。アプリ本体には不要です。

日時比較はUnixミリ秒を使用します。表示する暦日はブラウザのタイムゾーンに依存せず日本時間です。枠は月〜金9:00〜18:00、30分×90枠で、`予定開始 < 枠終了 && 予定終了 > 枠開始`で判定します。キャンセル済みイベントはブロックしません。予定名はタイトル・アクセシビリティ用テキストとして安全なDOM操作で表示します。

## ICS対応範囲

VERSION 2.0のVCALENDAR / VEVENT、UID、DTSTART、DTEND、SUMMARY、STATUSに対応します。日時はAsia/Tokyo、UTC（Z）、タイムゾーンなし（Asia/Tokyo扱い）。CALSCALEは未指定またはGREGORIANのみ許可し、他の暦はエラーにします。TZID・VALUEは未指定を許可しますが、明示された空値はエラーにします。終日はVALUE=DATEで終了日を含めません。終日でDTENDがない場合は1日とします。時刻付き予定にはDTENDが必要です。折り返し行と文字列の改行・カンマ・セミコロン・バックスラッシュのエスケープに対応します。エスケープは左から順に復元し、不正な文字や末尾の不完全なエスケープはエラーにします。STATUS未指定はCONFIRMEDとして扱います。

以下はファイル単位のエラーとなります。未対応機能を部分的に無視して空き時間を表示することを避けています。

- 繰り返し（RRULE、RDATE、EXDATE、EXRULE、RECURRENCE-ID）。
- Asia/Tokyo以外のTZID、VTIMEZONE、VALARM等の追加コンポーネント。
- DURATION、TRANSP（透明予定）、未知の標準プロパティや日時パラメーター。
- PUBLISH以外のMETHOD、VERSION 2.0以外、不正な日付・逆転した終了時刻。

DESCRIPTION、LOCATION、DTSTAMPなどの補助情報とX-拡張情報は判定に使いません。X-WR-TIMEZONEはAsia/Tokyoのみ許可します。VTIMEZONEを含む一般的なカレンダー書き出しは、そのままでは取り込めない場合があります。

## 検証結果

CodexクラウドのChromiumとPython Playwrightで確認しました（ブラウザのTZはAmerica/Los_Angeles）。

- サンプル300件を取得し、全件の開始・終了時刻をPythonによる独立したJST変換と照合：合格。
- グレー・緑・赤の枠、90枠、予定枠のクリック無効、空き枠のダイアログ：合格。
- 同一ファイル再読み込み、複数ファイル、ドラッグ＆ドロップ、クリア、週移動（7月・10月・今週）：合格。
- 不正ICS・未対応繰り返し・FileReader読み込み失敗時の既存データ保持：合格。
- UTC、終日、日またぎ、複数予定の重なり、キャンセル除外、10:15〜11:15、開始終了境界：合格。
- レビュー修正後の全10テストグループ：成功10・失敗0（既存機能1グループ＋追加回帰9グループ）。正常・不正エスケープ、暦の許可・拒否、空パラメーター、同一UIDの日時・状態更新、後続予定が不正なファイルの全体取り消し、読み込み途中のクリアと再取り込み、HTML文字列の安全な表示を含みます。
- 非同期読み込みはimportQueueの完了を待って検証します。読み込み途中のクリアはFileReaderの完了を手動制御し、固定時間待機は使用しません。
- JavaScriptのページエラー：0件。
- `file://`での直接起動：クラウドChromiumの管理ポリシーでブロックされるため未確認。テストは一時HTTP配信で実施しています。
- WindowsのEdge、実際のOSファイル選択ダイアログ、実マウスによるドロップ、スマートフォンでの目視確認：未確認。自動テストはファイル入力とドロップイベントを使用します。

再実行（Python Playwright導入済みの検証環境）：`python tests/test_browser.py`。直接起動が制限される環境では別ターミナルで`python -m http.server 8000 --bind 127.0.0.1`を起動し、`TEST_URL=http://127.0.0.1:8000 python tests/test_browser.py`を実行します。
